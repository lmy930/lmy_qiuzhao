## 每日自动搜集
.github/workflows/daily-discovery.yml 每天北京时间 10:00、22:00 开始运行官网优先的多来源采集，再搜索657家企业的2027届招聘线索。这是计划启动时间，不是网页更新完成时间；日常扫描任务最多运行35分钟；周日22:00深度回溯最多90分钟，随后执行网站部署，GitHub 排队可能进一步延迟。可在 Actions → Daily recruitment discovery → Run workflow 手动诊断，但日常使用无需手动操作。

搜索结果存放在 data/leads.json，仅供待核验；**不直接认定已开启**，以免误导投递。data/companies.json 中状态、招聘开启日期、截止时间、网申链接必须核验官网、政府、高校招聘正文或严格跨源佐证后方能更新。

注意：GitHub Actions 免费定时运行不是秒级实时监控，存在延迟和外部搜索服务不可用的可能。搜索覆盖657家名单，但来源索引和读取能力仍不完整，不能将搜索请求成功视为企业核验成功。

## 自动核验与日期证据

开发环境只需 Python 3.12 和 Node.js，不依赖第三方包。运行：

```sh
python -m unittest discover -s tests -v
node tests/check_frontend.mjs
node tests/check_dashboard.mjs
```

每日 Actions 在发现线索后运行 `scripts/verify_pages.py`，自动回访政府、高校和已登记的企业官网正文。已确认但没有网申日期的企业也会继续回访。`python scripts/verify_pages.py --dry-run` 可检查而不修改企业数据，但仍生成扫描报告；`--limit N` 可限制诊断请求数量。

后台严格日期仅采用 `open_date_evidence` 中有原文、目标届别、来源及企业范围的开启日期。旧记录中未留原文的日期继续保存在数据里供自动回溯，不计为“确切开启”。公告日、首次确认日、截止日和“即日起”都不能替代网申起始日期。旗下单位的日期保存为 `subsidiary_openings`，不写成集团统一开启日期；共享的 TCL 品牌不能直接区分 TCL 科技和 TCL 实业。

`data/page_verification_report.json` 记录本次读取、匹配、日期冲突和站点失败。全部正文读取失败时命令返回非零，Actions 不发布该轮数据，并上传诊断报告；部分站点失败时保留既有证据。搜索返回响应不等于核验成功。原始网页依赖 JavaScript、验证码、图片或封闭 API 时，当前文本采集仍不能保证覆盖，需要继续增加对应站点适配。不得通过降低核验标准来提高数量。


## 已开启企业看板

首页按银行、央企、民营500切换已确认启动的企业，提供搜索和投递状态筛选。首页已移除完整企业目录、日历和额外统计区；657家名单与日期证据继续保留在后台。首页不再依赖真实开启日期组织信息，后台仍继续回溯，绝不以公告日期或系统确认日填充开启日。

`data/launch_baseline.json` 是2026-10-11建立的固定确认基线，共150家。它是截至基线时已有证据的名单，不是“当天实际开启”的名单，也不意味着所有已开企业都已经找到。每日扫描不重写此文件。之后新确认的企业自动显示橙色“新确认”并排在前面，基线企业为灰蓝色；刷新、跨天、已读或投递标记不改变新旧分类。可按“后来新确认”和“首次基线”单独筛选。多分类企业会出现在对应多个类别，所以类别数量不能直接相加。

投递标记沿用原浏览器存储键；已投递和暂不投会持续保留，提供备份/恢复，手机电脑不自动同步。已记录结束的企业仍可查询，但不列入未投递清单。基线读取失败时继续显示企业和投递记录，不猜测新旧，也不显示零新增。最近正文核验失败或结果过期时说明当前是已保存信息。

2026-10-11本轮广泛查漏读取1,450个来源列表和候选正文页面，最终全量正文回访读取650/694页；另从西南交大实际公开JSON正文接口核验2页。已确认企业由101补充到150，新增49家，真实开启日期严格证据由4家补充到11家。每日生成的`data/coverage_report.json`保留尚未补齐正文哈希的既有记录和未确认数量；这些缺口继续自动回访，不能称为已全面找到。

正文回访现在也包含粉笔、中公、高顿等已登记招聘来源，支持文章 JSON 接口并跟进正文内的已知企业官网链接。单篇转载只保存候选日期；不同招聘机构的正文一致、不是完全相同转载且没有日期冲突时可作为交叉佐证，保留每篇的引文、机构和哈希。官网/政府/高校的直接日期依据优先，仍须核对企业、届别和集团/旗下单位范围。完整文章中靠后的报名时间和明确报名起止区间可解析；没有日历年份的月份、仅“即日起”或公告发布时间不能硬填开启日。

`daily_changes.json` 的 `first_confirmed` 记录系统新确认，`date_verified` 记录新补齐的实际日期。重复扫描同一证据不会每天重复生成更新。开启日和截止日均有原文时，报名区间用于判断当前已开启或已结束；截止信息未知时不会推断仍可投递。


## 广泛查漏与来源绑定

`scripts/broad_sources.py`先访问已登记的企业官网和已从招聘正文证明的企业专属网申渠道，再遍历高校招聘档案。日常采集最近页，每周日22:00自动深度回溯，无需用户手动触发；`--backfill`沿实际分页链接深度回溯，Actions手动诊断输入 `historical_backfill=true` 可启用。本云环境19处高校入口中6处可读；GitHub实际深度扫描中12处入口可读，并读取139个官网及其招聘栏目页面。入口/页面读取不等于企业核验完成，失败和索引缺口逐项记录，不能声称19处来源或657家已全面覆盖。

标题只产生线索；政府、聚合来源也不直接改变招聘状态。招聘正文必须有2027届明确标题/内容、实际岗位或报名内容及目标企业身份。未知品牌需正文公司介绍的法律名称与简称对应；集团旗下单位需明确隶属关系，客户或合作伙伴提及不算。高校正文内的企业专属智联/北森等渠道按租户或企业路径绑定，保留原始公告作为证明，不全域信任招聘平台。西南交大的公开正文JSON使用其网页实际调用的匿名接口读取并保留原始响应哈希。

2026-10-11还实际回看103份已有正文，修复投递时间表、复合“投递开始时间”、明确共同招聘资格和带时刻区间的解析；月份范围不会被截断成精确日期，首批招聘保留批次。中国电信、中广核、招商银行首批、浦发银行、哈尔滨银行新增严格日期依据，原文引文/哈希留存后台。GitHub深度扫描与自动发布已实际通过：[运行记录](https://github.com/lmy930/lmy_qiuzhao/actions/runs/38136265954)。
