## 网页发布
仓库 Settings → Pages → Build and deployment → Source 选择 GitHub Actions（一次性配置）。`publish-site.yml` 在 main 的页面或数据更新后部署；每日扫描成功后也直接调用同一发布流程，不依赖机器人提交再次触发 push 工作流。日常查看固定网址即可，无需手动运行扫描或发布。

## 每日自动搜集
.github/workflows/daily-discovery.yml 每天北京时间 08:40、20:40 开始调用 scripts/discover.py，分批滚动查询企业的 2027 届招聘线索。这是计划启动时间，不是网页更新完成时间；扫描任务最多运行35分钟，随后执行网站部署，GitHub 排队可能进一步延迟。可在 Actions → Daily recruitment discovery → Run workflow 手动诊断，但日常使用无需手动操作。

搜索结果存放在 data/leads.json，仅供待核验；**不直接认定已开启**，以免误导投递。data/companies.json 中状态、招聘开启日期、截止时间、网申链接必须核验企业官方公告后方能更新。

注意：GitHub Actions 免费定时运行不是秒级实时监控，存在延迟和外部搜索服务不可用的可能。每日只批量检查部分企业，官网核实流程仍需后续完善。

## 自动核验与日期证据

开发环境只需 Python 3.12 和 Node.js，不依赖第三方包。运行：

```sh
python -m unittest discover -s tests -v
node tests/check_frontend.mjs
node tests/check_dashboard.mjs
```

每日 Actions 在发现线索后运行 `scripts/verify_pages.py`，自动回访政府、高校和已登记的企业官网正文。已确认但没有网申日期的企业也会继续回访。`python scripts/verify_pages.py --dry-run` 可检查而不修改企业数据，但仍生成扫描报告；`--limit N` 可限制诊断请求数量。

网页日历仅采用 `open_date_evidence` 中有原文、目标届别、来源及企业范围的开启日期。旧记录中未留原文的日期继续保存在数据里供自动回溯，不计为“确切开启”。公告日、首次确认日、截止日和“即日起”都不能替代网申起始日期。旗下单位的日期保存为 `subsidiary_openings`，不写成集团统一开启日期；共享的 TCL 品牌不能直接区分 TCL 科技和 TCL 实业。

`data/page_verification_report.json` 记录本次读取、匹配、日期冲突和站点失败。全部正文读取失败时命令返回非零，Actions 不发布该轮数据，并上传诊断报告；部分站点失败时保留既有证据。搜索返回响应不等于核验成功。原始网页依赖 JavaScript、验证码、图片或封闭 API 时，当前文本采集仍不能保证覆盖，需要继续增加对应站点适配。不得通过降低核验标准来提高数量。


## 已开启企业看板

首页按银行、央企、民营500切换已确认启动的企业，提供搜索和投递状态筛选。完整目录及日期证据收起。首页不再依赖真实开启日期组织信息，后台仍继续回溯，绝不以公告日期或系统确认日填充开启日。

`data/launch_baseline.json` 是2026-10-11建立的固定确认基线，共101家。它是截至基线时已有证据的名单，不是“当天实际开启”的名单，也不意味着所有已开企业都已经找到。每日扫描不重写此文件。之后新确认的企业自动显示橙色“新确认”并排在前面，基线企业为灰蓝色；刷新、跨天、已读或投递标记不改变新旧分类。可按“后来新确认”和“首次基线”单独筛选。多分类企业会出现在对应多个类别，所以类别数量不能直接相加。

投递标记沿用原浏览器存储键；已投递和暂不投会持续保留，提供备份/恢复，手机电脑不自动同步。已记录结束的企业仍可查询，但不列入未投递清单。基线读取失败时继续显示企业和投递记录，不猜测新旧，也不显示零新增。最近正文核验失败或结果过期时说明当前是已保存信息。

2026-10-11实际正文扫描读取117/120页，核验接受53家既有企业，无新增企业或新证据日期。修复了只有未来截止日、没有开启日时触发空日期比较导致整轮扫描中断的问题，并纠正研究中心招聘的集团/旗下单位范围。当前仍只有4家有严格真实开启日期证据；其他日期继续待回溯，不冒充已验证。

正文回访现在也包含粉笔、中公、高顿等已登记招聘来源，支持文章 JSON 接口并跟进正文内的已知企业官网链接。单篇转载只保存候选日期；不同招聘机构的正文一致、不是完全相同转载且没有日期冲突时可作为交叉佐证，保留每篇的引文、机构和哈希。官网/政府/高校的直接日期依据优先，仍须核对企业、届别和集团/旗下单位范围。完整文章中靠后的报名时间和明确报名起止区间可解析；没有日历年份的月份、仅“即日起”或公告发布时间不能硬填开启日。

`daily_changes.json` 的 `first_confirmed` 记录系统新确认，`date_verified` 记录新补齐的实际日期。重复扫描同一证据不会每天重复生成更新。开启日和截止日均有原文时，报名区间用于判断当前已开启或已结束；截止信息未知时不会推断仍可投递。
